## 0. 三点澄清（先回答你的问题）

### 0.1 「粘贴为纯文本」在哪个右键菜单？

**面板列表里每条记录上右键**——就是现在弹出「Bing」等扩展动作的**同一个菜单**，不是 SnipDo 的菜单，
也不是托盘菜单。菜单结构（v1.1.0 后）：

```
右键任意条目
├── 粘贴为纯文本            ← 新增内置项（仅文本类条目显示）
├── ─────────────
├── Bing                    ← 你已导入的 SnipDo 扩展动作
└── 写入文件（示例扩展）
```

### 0.2 跟我的 SnipDo 插件怎么联动？

**同一入口、两条管道**，互不干扰：

| | 「粘贴为纯文本」 | SnipDo 扩展动作（如 Bing） |
| --- | --- | --- |
| 来源 | ClipBar 内置 | 你导入的 SnipDo 包 |
| 执行 | 走 ClipBar 粘贴安全链（激活原窗口→失败不发键→三态提示） | 走 SnipDo 语义（URL/PowerShell/Python/按键） |
| 依赖 | 无 | 依赖扩展包与 SnipDo 约定 |

换句话说：**你的 Bing 完全不受影响**；纯文本粘贴只是菜单里多了一项更可靠的内置能力。
另外 C5（stdin JSON）会让**脚本类**扩展拿到更多上下文，属加强联动、不改变既有行为。

### 0.3 脚本 stdin JSON 到底用在哪？

**用在你导入的 PowerShell / Python 类扩展动作的脚本里**（Bing 是 URL 类，不经过脚本，用不到）。

- **今天的问题**：脚本只能拿到 `-PLAIN_TEXT` 这类纯文本参数。如果你复制的是**一组文件**，
  脚本根本不知道有哪些文件——文件路径、HTML、来源应用全拿不到。
- **改造后**：ClipBar 调脚本时，除了原有参数，再从标准输入喂一段 JSON：

```json
{
  "text": "被复制的文本",
  "html": "<b>富文本</b>",
  "filePaths": ["C:\\Users\\me\\Desktop\\报告.docx"],
  "sourceApp": "msedge",
  "options": { "engine": "bing" }
}
```

- **脚本里怎么用**（PowerShell，两行）：

```powershell
param([string]$PLAIN_TEXT)              # 老参数照旧可用
$ctx = [Console]::In.ReadToEnd() | ConvertFrom-Json
if ($ctx.filePaths) { Compress-Archive -Path $ctx.filePaths -DestinationPath out.zip }
```

- **能多做什么**：比如写一个「把刚复制的几个文件打包发送」的扩展——这是当前参数体系做不到的。
- **兼容性**：不读 stdin 的老脚本零影响；ClipBar 内置的 Bing 这类 URL 动作不经过脚本，无感。

## 2. 条目明细

### A1 粘贴为纯文本

- **做什么**：右键菜单顶部新增内置项「粘贴为纯文本」（图标 `TextCaseTitle24`，排在扩展动作之上并加分隔线）。
  执行 = 只写回 `UnicodeText`（跳过 HTML 分支）后走既有粘贴链（激活目标、Ctrl+V、三态结果）。
- **必要性**：带 HTML 的条目粘贴**永远带格式**，贴进聊天框/代码编辑器是高频痛点；竞品全部内置。
- **实现要点**：`PasteService.SetClipboardAsync` 增加 `plainTextOnly` 参数（文本类才有效，图片/文件条目菜单不显示此项）；
  纯文本时跳过 `HtmlFormatHelper`；菜单项对非文本条目隐藏。
- **验收**：带 HTML 的条目执行后目标收到无格式文本（剪贴板枚举无 HTML 格式）；图片/文件条目无此项；单测覆盖 plain-text-only 写回分支。
- **测试**：PasteServiceTests 新增 2 例（纯文本写回无 HTML 格式；图片条目不产生菜单项的 VM 层判定）。

### A2 托盘「暂停捕获」

- **做什么**：托盘菜单「暂停捕获 / 恢复捕获」互斥项（勾选态）；暂停时 `ClipboardMonitor.CaptureAsync` 早退；
  托盘 tooltip 追加「（已暂停）」；**重启后恢复为开启**（暂停是会话级状态，不持久化——避免忘记恢复导致长期漏采）。
- **必要性**：临时复制敏感内容、批量复制垃圾时不想被记录；现在只能退出整个软件。
- **验收**：暂停→复制→DB 计数不变；恢复→正常入库；重启后为开启态；tooltip 文案正确。
- **测试**：ClipboardMonitor 抽出可测 seam（暂停标志注入），新增暂停/恢复 2 例。

### A3 粘贴后保持面板打开

- **做什么**：设置页「行为」加复选框「粘贴后保持面板打开」（默认关=现行为）；开启时 `PasteItem` 跳过 `Hide()`，
  粘贴链照常（激活目标、Ctrl+V），面板保持可见；连续粘贴多次。
- **必要性**：连续贴 3 条不同内容现在要按 3 次热键。
- **验收**：关=现行为；开=面板保持且目标逐字符收到内容、焦点在目标；设置入 Normalize/ContentEquals； dirty 状态正确。
- **测试**：设置字段入 Clone/ContentEquals 矩阵各 1 例；PasteItem 分支以可注入 seam 验证（不停留面板时不 Hide）。

### A4 图片另存为文件

- **做什么**：图片条目右键菜单加「图片另存为…」：`SaveFileDialog` 默认文件名 `图片 {w}×{h}.png`，写入失败 Toast。
- **必要性**：截图只能存在于历史里，补齐「复制→保存」闭环。
- **实现要点**：从既有 PNG 文件直接复制（不重编码）；目标被占用/无权限→Toast 报错不崩溃。
- **验收**：保存成功且文件可用图片查看器打开；取消无副作用；非图片条目无此项。
- **测试**：ImageStore 新增 `SaveAs(source, target)` 纯文件复制方法 + 3 例（成功/重名覆盖拒绝/源缺失）。

### A5 面板尺寸可调 + 记忆（含布局约束，用户特别关注）

- **做什么**：`ResizeMode=CanResize`（MinWidth=360 / MinHeight=480）；关闭或隐藏时把
  `Left/Top/Width/Height` 写入 AppSettings（Normalize/Clone/ContentEquals 同步）；启动恢复存储值，
  无值回落鼠标屏居中；恢复值夹取在目标显示器工作区内。
- **布局硬约束**（防止控件/文字挤压换行，验收时逐条检查）：
  1. 所有文本行**单行 + 省略号**（`TextWrapping=NoWrap` + `TextTrimming=CharacterEllipsis`），禁止随宽度换行；
  2. 行高固定：文本行/小档行 60 DIP、分组标题 26 DIP——不随面板宽度变化；
  3. 筛选按钮行**固定不换行**，超出宽度时水平裁切（不堆叠）；
  4. 搜索框、列表、页脚用 `*` 弹性列，固定列只允许图标/按钮（≥24×24 DIP 触达区）；
  5. 页脚按钮固定尺寸，计数文本超宽时省略（不挤压右侧按钮）；
  6. 大图预览已按内容宽自适应（转换器），窄面板下继续等比缩小，不产生横向滚动；
  7. 三档预览在 MinWidth=360 下逐档验证不溢出卡片。
- **验收矩阵**（每格截图 + 逐条约束检查）：尺寸 {360×480 最小 / 420×620 默认 / 640×800 / 1000×1000} ×
  缩放 {100% / 125% / 200%} × 主题 {浅 / 深} × 内容 {空 / 129 条真实量级 / 长文本+四类条目}。
- **测试**：AppSettings 几何字段入 Clone/ContentEquals/Normalize 矩阵；PanelPlacement 恢复夹取单测 3 例。
- **风险控制**：若 360×480 下出现不可接受的挤压，提高 MinWidth 而不是放宽约束——约束优先于灵活性。

### A6 删除撤销

- **做什么**：删除后 Toast「已删除 · 撤销」5 秒；撤销 = 同 Id 重新入库（updatedAt 保持原值，回到原位置）；
  图片文件先移入 `images/trash/`，撤销移回，Toast 超时后由既有孤儿清扫删除 trash。
- **必要性**：删除是最高频破坏性操作且目前立即删文件，手抖=永久丢失（V2 轮 D-F-02 遗留项）。
- **隐私说明**：撤销窗口期内被删内容短暂可恢复，属设计行为；清空全部不受影响（仍二次确认+硬删）。
- **验收**：删除→撤销→条目原位恢复且图片条目图片可用；不撤销→trash 清扫后文件消失；清空全部不产生 trash。
- **测试**：MainViewModel 撤销命令 3 例（文本恢复/图片恢复/超时清理）；trash 清扫单测 2 例。

### A7 搜索命中高亮

- **做什么**：条目标题中对搜索子串加强调色高亮（VM 层拆分 Run，不动 SQL）；无搜索时无高亮。
- **验收**：中文/英文/大小写不敏感命中均高亮；清空搜索恢复；多条命中全部标出。
- **测试**：高亮拆分纯函数单测 4 例（无命中/单命中/多命中/大小写）。

### A8 日期/来源过滤

- **做什么**：筛选行追加「今天 / 7 天」时间档与来源应用下拉（来源 = 现有条目 SourceApp 去重，取前 N+「全部来源」）；
  过滤在 VM 层组合（SQL 不变），与搜索/类型叠加。
- **验收**：组合「图片 + 今天 + msedge」结果正确；清空一键复位；无来源条目时下拉不出现。
- **测试**：过滤组合纯函数单测 6 例；UIA 走查 1 轮。

### C1 SQLite 迁移机制（地基，无行为变化）

- **做什么**：`InitializeAsync` 读 `PRAGMA user_version`，按版本递增执行迁移（本轮 v1→v2 **不加列**，仅建机制 + 迁移记录表）。
- **必要性**：现在加任何列=老库查询崩溃（按序数读取）；现在 30 行，用户库铺开后是数据丢失级事故。
- **验收**：新库 user_version=2；手工把 user_version 改回 0/1 的旧库启动自动升 2 且数据不变；迁移在事务内。
- **测试**：迁移步骤单测 3 例（全新库/降级库/损坏中断重试）。

### C2 settings.json 版本字段

- **做什么**：AppSettings 加 `Version=2`；JsonSettingsStore 写入带 version；Normalize 校验 Theme/Preview 合法值。
- **验收**：无 version 旧文件读入默认并正常；未知 Theme 归一；往返保留。
- **测试**：3 例（无 version/未知字段容忍/往返）。

### C3 数据目录可重定向

- **做什么**：AppPaths 改静态 `Initialize(dataDir?)`：`--data-dir X` 参数或 exe 旁 `portable.marker` 决定目录；
  互斥体/事件名随目录哈希派生（便携双副本不冲突）；无参数行为与现在完全一致（含旧目录迁移）。
- **验收**：`--data-dir X` 启动后 db/settings 落在 X；无参行为回归不变；双副本可同时跑（不同目录）。
- **测试**：路径派生与迁移守卫单测 5 例。

### C4 动作执行注册表

- **做什么**：`ExtensionActionRunner` 的 switch 改为 `Dictionary<SnipDoActionKind, IActionExecutor>`（组合根装配）；
  runner 的 UI 通知改注入 `Action<string>`。
- **必要性**：加动作类型从改 4 处变注册 1 处；A1/A4 的内置动作将来以统一方式接入。
- **验收**：现有 URL/PowerShell/Python/KeyCombo 行为回归不变（388+ 例 + 扩展动作实测）；新增类型只需注册。

### C5 脚本 stdin JSON API

- **做什么**：PowerShell/Python 执行时经 stdin 传
  `{"text":…,"html":…,"filePaths":[…],"sourceApp":…,"options":{…}}`（UTF-8）；argv 参数**原样保留**；
  Bing 等 URL 动作不涉及。
- **必要性**：让脚本扩展拿到文件列表/HTML/来源等完整上下文（见 0.3）。
- **验收**：新写 demo 脚本读取 JSON 成功拿到 filePaths；旧脚本（忽略 stdin）行为不变；超时/编码 UTF-8 无 BOM。
- **测试**：stdin 注入 seam 单测 3 例（JSON 结构/argv 兼容/编码）。

## 3.x 面板尺寸约束的验收清单（A5 专项，逐格执行）

| 尺寸越界 | 试图调到 <Min 会被夹取；最大化按钮不存在 |

## 4. 连续执行顺序（中途不停顿、不单独发版）

```
阶段一  A2 → A3 → A1 → A4          （每项：实现+测试+提交）
阶段二  C1 → C2 → C3               （地基先行，A5 依赖 C3 的目录测试隔离）
阶段三  A5 → A6 → A7 → A8          （A5 最重，留独立验收矩阵）
阶段四  C4 → C5 → 全量回归 → 发布 v1.1.0 → 实测验收清单逐条执行
```

- 排序理由：地基（C1-C3）在功能收口前建好，避免 A5/A6 的存储字段写进无版本机制的文件；
  A5 放地基后是因为要借 C3 的测试隔离；每阶段结束跑一次全量测试（388 → 400+ 例）。
- 每阶段完成标准：新增测试全绿 + 全量测试全绿 + 编码检查 OK + 提交。
- 最终发布 v1.1.0：GitHub Release 资产双 exe + Release Notes（含新功能说明与截图）。

## 5. 发布门禁（v1.1.0 全部满足才发）

1. 全量测试 ≥ 400 例全绿（含本版本新增 ≥12 例）；
2. 编码检查 OK；隐私扫描 OK；
3. A5 验收矩阵全格通过；
4. 真机走查：右键纯文本粘贴落字符、暂停捕获生效、保持面板连续三贴、另存为落盘、撤销恢复；
5. 双版本发布 + Release Notes（含截图）。

## 6. 回退策略

v1.1.0 回退到 v1.0.0 不涉及数据兼容问题。
