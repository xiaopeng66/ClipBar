# 面板存活与消失规则

面板是临时弹窗，不是常驻窗口。总原则：**用户点击面板外的任何地方，面板都应消失**；只有“属于面板的操作”（菜单、面板自己的对话框、连续粘贴）可以短暂压住这条规则，且压住结束后必须补上判断。

本文对应 v1.1.2 的实现（`MainWindow.Window_Deactivated` / `SuppressAutoHide` / `AttachMenuLifetime` / `PanelDismissPolicy`）。

## 规则表

| 场景 | 菜单 / 对话框 | 面板 | 说明 |
| --- | --- | --- | --- |
| 普通失焦：点桌面、任务栏、别的应用 | — | 消失 | `Window_Deactivated` 直接隐藏 |
| 右键动作菜单打开 | 保留 | 保留 | 菜单是独立窗口，打开时面板必然失焦，需要抑制 |
| 菜单打开时点面板内 | 关闭 | 保留并获得焦点 | 点击本身已激活面板 |
| 菜单打开时点面板外 | 关闭 | 消失 | 延迟检查发现面板仍非活动 |
| 菜单按 Esc | 关闭 | 保留并获得焦点 | 视为“回到面板” |
| 菜单点某项 | 关闭 | 保留，由动作决定 | 来源筛选保留；粘贴动作走粘贴规则 |
| 确认 / 通知 / 扩展选项 / 另存为对话框 | 保留 | 保留在对话框后 | 对话框关闭后焦点回到面板 |
| 设置窗口打开 | — | 消失 | 设置是独立窗口，不属于面板弹窗 |
| 点条目粘贴（保持打开 = 关） | — | 立即消失，再粘贴 | 默认行为 |
| 点条目粘贴（保持打开 = 开） | — | 粘贴完成后保留并重新激活 | 便于连续粘贴；之后点外部仍会消失 |
| Esc / 关闭按钮 | — | 消失 | |
| 应用退出 | — | 不拦截 | `_allowClose` |

说明：模态对话框打开期间，Windows 会禁用所有者窗口，点到面板外不会关闭对话框；面板在对话框关闭后按“是否重新获得焦点”决定去留。这是系统模态语义，不做特殊绕过。

## 实现要点

1. `Window_Deactivated`
   - 只在“显示序列已完成”（`_showCompleted`）后生效；窗口刚 Show 时的失焦通知属于显示过程，不隐藏。
   - 没有抑制作用域：直接 `Hide()`。
   - 处于抑制作用域：只置 `_deactivatedWhileSuppressed = true`，不立即隐藏。
   - 不依赖 `Activated` 事件来开启这条规则：重复显示时 WPF 可能不再发 `Activated`（窗口仍被视为活动），旧标记会一直为 false，失焦隐藏就被静默关掉了。
2. `SuppressAutoHide()` 是嵌套计数作用域。最后一个作用域 `Dispose()` 时，如果期间发生过失焦，用 `Dispatcher.BeginInvoke(DispatcherPriority.Input)` 延后一轮判断：
   - 面板仍可见、非退出、**前台窗口不属于本进程** → `Hide()`（`PanelDismissPolicy.ShouldDismiss`）。
   - 前台是本进程的窗口（面板本身、面板的对话框、下一个菜单）→ 保留。
   - 延后一轮是必要的：菜单关闭与面板激活的通知顺序不固定，只有消息循环跑完一轮，前台窗口才是稳定值。
   - 不能用 `Window.IsActive` 判断：拥有的菜单关闭时 WPF 会把所有者标成活动，即使那一击其实落在别的应用上。
3. 菜单关闭（`TrayMenuWindow.ClosedByDeactivation`）
   - Esc 或点菜单项：`ForceForeground()` 把焦点交回面板；延迟判断看到前台是本进程 → 保留。
   - 失焦关闭且指针在面板矩形内：实测此时 Windows 会把焦点交还给菜单打开前的那个外部应用，而不是面板，因此不能只信前台窗口；用光标位置确认“点的是面板”，再 `ForceForeground()` 收回焦点。
   - 失焦关闭且指针在面板外：不抢焦点，延迟判断看到前台是外部应用 → 面板一起消失。
4. 保持打开（`KeepPanelOpenAfterPaste`）
   - 粘贴期间用抑制作用域挡住“目标窗口激活导致面板失焦”。
   - 粘贴键发出后不立刻抢焦点：先等 ~150 ms 让目标应用处理完，再 `ForceForeground()` 并校验前台确实是面板（最多 4 次、每次 80 ms）；成功后 `Dispose()`，延迟判断看到本进程前台 → 保留。
   - 之后没有任何抑制，用户点外部 → 常规 `Deactivated`（或前台看门狗）→ 消失。
5. 设置窗口刻意**不**抑制：打开设置即失焦，面板隐藏；设置窗口按普通窗口语义存活。
6. 前台看门狗（兜底）：面板可见且未被抑制时，每 200 ms 检查一次前台窗口；连续 3 次（约 600 ms）不属于本进程就隐藏。`Deactivated` 是快路径，但实测存在 Windows 已把前台切走、WPF 却没收到失焦通知的情况（尤其保持打开粘贴之后），只靠事件会漏掉“点外部不消失”。600 ms 阈值可以避开通知气泡之类的瞬时抢焦点。
7. 已删除旧实现里的 120 ms 延时和光标矩形判断：那是在猜“刚才那一击落在哪”；现在改为判断“抑制结束后前台是否还是本进程的窗口”，并用 `ClosedByDeactivation` 区分 Esc/选项与失焦。

## 回归测试

- `PanelDismissPolicyTests`：失焦后前台属于别的进程 → 消失；点击回面板 / 对话框归还焦点 → 保留；隐藏或退出优先。
- 实测验收：菜单打开时点外部（菜单+面板消失）、点面板内（面板保留）、按 Esc（面板保留）；普通点外部消失；保持打开粘贴后点外部消失。
- `PanelPlacementTests`：跟随鼠标在 125% ↔ 200% 显示器之间居中。
