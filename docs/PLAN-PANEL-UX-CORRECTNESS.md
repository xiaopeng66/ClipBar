# ClipBar 面板首帧、定位与生命周期修复方案

- 版本：2026-11-05
- 范围：首帧加载、三种位置模式、设置草稿生命周期、右键菜单激活、失焦隐藏速度、底部筛选入口
- 测试原则：所有压力测试使用隔离 `--data-dir`，不删除或改写真实 `%LOCALAPPDATA%\ClipBar` 历史库

## 1. 问题证据与目标

| 问题 | 当前证据 | 目标 |
| --- | --- | --- |
| 首次唤起先显示空壳 | `MainWindow.ShowPanel()` 先 `Show()`，再调用 `RefreshInBackground()`；`Items` 初始为空 | 首次可见帧已经包含历史行，空库则直接显示明确空状态 |
| 位置语义不清且缺少指针旁模式 | `FollowCursor` 实际为鼠标所在显示器居中 | 提供“记住上次位置 / 鼠标所在显示器居中 / 跟随鼠标指针（智能展开）” |
| 设置未编辑也提示未应用 | `BuildCandidate()` 漏复制 `PanelPositionInPixels` | 未编辑关闭不提示；确认丢弃后重开为 live 设置且干净 |
| 右键菜单偶尔失焦、边框变淡 | 菜单同步显示；激活结果未验证；1 DIP 边框未像素吸附 | 菜单显示在右键输入结束后，确认前台和焦点；边框稳定 |
| 点击外部消失慢 | `Deactivated` 漏掉时依赖 200ms × 3 watchdog；隐藏时同步写设置 | 失焦快路径立即隐藏，兜底只做短重试，写盘不阻塞视觉隐藏 |
| 右下角入口不合理 | 主面板 footer 有“清空”，来源漏斗在筛选行 | footer 右侧放来源筛选，清空仅保留在设置/托盘 |

## 2. 三种位置定义

1. `Remember`：恢复上次保存的物理坐标，按目标显示器 DPI 夹取。
2. `MonitorCenter`：以唤起瞬间鼠标所在显示器的工作区为目标，面板居中。
3. `CursorAnchor`：以唤起瞬间鼠标物理坐标为锚点，按右/左、下/上剩余空间分别选择方向；不足时翻转并夹取。它是“每次唤起时跟随指针”，不是持续追踪。

旧设置值 `FollowCursor` 迁移为 `MonitorCenter`，不改变已有用户行为。

## 3. 实施顺序

1. 添加初始加载门，启动时在窗口可见前预加载历史；补空库/失败状态。
2. 增加位置模式、DPI/负坐标/四象限数学和设置 UI。
3. 从 `_applied.Clone()` 构建设置候选，修复丢弃/重开/隐藏复用。
4. 修复右键条目命中、菜单延迟激活、前台校验、焦点视觉和像素边框。
5. 将失焦兜底改成短重试，几何保存合并到空闲时执行。
6. 将来源按钮移动到 footer，删除主面板清空按钮。
7. 补单测、UIA/截图/时延实测，再进行编码检查与双版本构建。

## 4. 验收矩阵

### 首帧与数据

- 隔离目录中预置文本、图片、文件和多个来源；冷启动后第一次显示即能找到 ListItem。
- 空库第一次显示直接出现“复制的内容会出现在这里”，不能先出现空白外壳。
- 延迟查询只允许窗口保持隐藏；查询失败有明确错误/空状态且不吞异常。
- 连续唤起共享同一初始加载任务，不重复查询。

### 定位

- 三种模式分别在主屏、负坐标副屏、四角和贴边位置验证。
- 指针旁模式在右下角向左上展开，在左上角向右下展开，单轴不足时独立翻转。
- 125%/150%/200% DPI 下位置与尺寸不漂移。
- 旧 `FollowCursor` 设置仍表现为显示器居中。

### 设置

- 未编辑打开后关闭不弹确认。
- 编辑后选择“继续编辑”保留原窗口和内容。
- 编辑后确认关闭，再次打开显示原 live 值且不脏。
- 应用 A 后编辑 B，确认丢弃后仍为 A。
- `PanelPositionInPixels=true` 时初次打开不误报修改。
- 隐藏设置窗口再次打开不创建孤儿窗口。

### 菜单与失焦

- 普通文本、搜索高亮文本、图片、文件、来源漏斗各循环至少 20 次。
- 菜单 HWND 成为前台窗口，首个可用项可获得焦点；右键输入结束不会抢回 owner。
- 菜单外点时菜单和面板一起关闭；面板内点或 Esc 时只关闭菜单。
- 普通点击其他应用后面板在一个短输入窗口内消失；几何保存不阻塞 Hide。
- 深浅主题及 125%/150%/200% DPI 下边框不出现偶发虚影或透明度跳变。

### 布局

- 主面板 footer 右侧为来源筛选按钮，右下不再出现清空。
- 设置页和托盘仍保留清空入口。
- 最小窗口宽度下筛选 chip、footer、来源按钮不换行、不裁切。

## 7. 追加修复（同轮）

点击非激活表面（桌面/任务栏等）不产生失焦事件的问题已根除：面板可见期间安装
`WH_MOUSE_LL` 全局鼠标钩子（`OutsideClickHook`），mouse-down 时用 `WindowFromPoint` 判断点击
窗口归属，外部窗口立即隐藏——与 Ditto / PowerToys Run 的做法一致，不再依赖激活语义。抑制期
（菜单/对话框/保持打开粘贴）钩子放行，由各自生命周期处理；`Deactivated` 与 200 ms 前台看门狗
保留为无鼠标切换（Alt+Tab）与兜底路径。
## 8. 窗口首帧闪烁的根除（2026-11-06）

现象：深色主题下右键菜单打开瞬间仍会闪一下；面板唤起同样有半成品帧。

做法（采用 STranslate 的 DWM cloak 技术，见 `src/ClipBar.App/Platform/FlashFreeShow.cs`）：

- 窗口在 `SourceInitialized` 时设置 `DWMWA_CLOAK`，DWM 不合成它，但 WPF 继续布局/渲染；
- 首帧渲染完成后（`ContentRendered`，兜底为一次 ApplicationIdle）取消 cloak，并执行必须
  在可见后才做的激活/聚焦；
- 面板（`MainWindow`）、右键/来源/托盘菜单（`TrayMenuWindow`）、确认/通知/Toast
  （`FluentMessageWindow`）、扩展选项框（`AppOptionWindow`）、设置窗口均接入。

不采用窗口淡入：实测 `Window.Opacity` 在非透明（Acrylic）窗口上不生效——设为 0.4 会让整窗
不可见；要做真淡入必须改分层窗口，代价是丢失 Acrylic 背景。Win+V / PowerToys Run / Ditto
同样是即时出现、不做淡入。

实测：菜单 cloak 安装→释放 25–57ms，菜单 4/4 正常出现（临时调试热键触发，验证后已移除）；
面板首帧抓帧显示第一可见帧即完整内容。
